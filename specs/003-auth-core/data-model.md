# Data model: 003 Auth core

Migration: `apps/api/migrations/00003_auth.sql` (goose; version 00003 per plan P-18 / C-1: 002 owns `00002_scheduler_outbox.sql` and merges first). It only adds objects (expand-only) and is backward compatible with the previous app version, which does not read these tables. **Auth schema: owner approval and a security review are required** (constitution workflow 5 and 7).

Conventions (`.claude/rules/sql.md`):

- `uuidv7()` primary keys and `timestamptz`.
- `org_id uuid NOT NULL REFERENCES orgs(id)` on every table.
- CHECK constraints for enums and states, and foreign keys everywhere.
- All times are written from the injected clock (002's `clock.Func`) through `@now` parameters. Column defaults exist only as a safety net.
- Go types come from 002's sqlc override: `uuid` columns map to `github.com/google/uuid.UUID` (nullable: `uuid.NullUUID`).
- No plaintext secrets: `*_hash bytea` holds SHA-256 or HMAC digests, `*_enc bytea` holds the AES-GCM envelope (`internal/platform/crypto`).
- Email and mobile are readable by owner decision (ADR 0007).

The sketch below is the design. The implementer writes the final SQL, which must keep every constraint listed here.

## Entity overview

```text
orgs (001) 1──* users 1──* device_sessions 1──* refresh_tokens
                  │  1──0..1 admin_mfa
                  │  1──* mfa_recovery_codes
                  │  1──* mfa_challenges
orgs 1──* auth_throttles            (keyed by HMAC subject; no FK to users on purpose)
orgs 1──* audit_log (001, unchanged columns; written via 002's audit.Write; entity='user', entity_id=users.id)

Refresh-token family = one device_sessions row: all refresh_tokens of a session form its family.
```

## 1. `users` (spec entity: User; FR-001…FR-004, D-02…D-04, D-16…D-19)

| Column | Type | Constraints / notes |
|---|---|---|
| id | uuid | PK default `uuidv7()` |
| org_id | uuid | NOT NULL FK orgs |
| role | text | NOT NULL CHECK `role IN ('admin','client')` |
| status | text | NOT NULL CHECK `status IN ('pending_verification','pending_approval','active','disabled')` |
| status_before_disabled | text | NULL CHECK `IN ('pending_verification','pending_approval','active')`. CHECK `(status = 'disabled') = (status_before_disabled IS NOT NULL)` |
| name | text | NOT NULL CHECK `char_length(btrim(name)) BETWEEN 1 AND 200` |
| email | text | NOT NULL CHECK `email = lower(btrim(email)) AND char_length(email) BETWEEN 3 AND 254 AND position('@' in email) > 1` |
| mobile | text | NULL CHECK `mobile ~ '^\+91[6-9][0-9]{9}$'`. CHECK `role = 'admin' OR mobile IS NOT NULL` (clients must have a mobile) |
| email_verified_at | timestamptz | NULL |
| mobile_verified_at | timestamptz | NULL. CHECK `mobile IS NOT NULL OR mobile_verified_at IS NULL` |
| password_hash | text | NOT NULL CHECK `password_hash LIKE '$argon2id$%'` (PHC) |
| password_changed_at | timestamptz | NOT NULL |
| last_sign_in_at | timestamptz | NULL |
| created_at / updated_at | timestamptz | NOT NULL |

Indexes:

- `users_email_key UNIQUE (email)`: global (D-18 "across the whole system").
- `users_mobile_key UNIQUE (mobile) WHERE mobile IS NOT NULL`.
- `users_org_role_status_idx (org_id, role, status)`: used for the last-admin check and future client lists.

Status machine (D-02, FR-002, BR-CLI-04). Every transition writes `auth.user.status_changed` with before and after status:

```text
create(client) ─> pending_verification ──(email ✓ and mobile ✓, either order)──> pending_approval ──approve──> active
any non-disabled ──disable──> disabled (status_before_disabled := previous; ends all sessions)
disabled ──enable──> status_before_disabled (sessions stay ended)
bootstrap(admin) ─> active (email_verified_at := now)
```

Guards:

- Approval is allowed only from `pending_approval`.
- Disabling the last `active` admin of the org is refused (`auth.last_admin`). The check locks every admin row of the org, ordered by id, `FOR UPDATE`.
- Marking an already-verified contact again changes nothing and writes no audit entry.
- Sign-in requires `status='active'` (BR-CLI-04 gate).

## 2. `device_sessions` (spec: Device session; FR-022, FR-042, FR-047…049, D-06, D-11, D-12)

| Column | Type | Constraints / notes |
|---|---|---|
| id | uuid | PK (`sid` claim) |
| org_id | uuid | NOT NULL FK orgs |
| user_id | uuid | NOT NULL FK users |
| device_id | uuid | NOT NULL. Installation identity generated by the app (UUID). The app stores it next to the refresh credential. |
| device_name | text | NOT NULL CHECK length 1–100 (informational) |
| platform | text | NOT NULL CHECK `IN ('android','iphone','web')` |
| client_type | text | NOT NULL CHECK `IN ('mobile','web')`: refresh transport (P-04) |
| mfa_method | text | NULL CHECK `IN ('totp','recovery_code','enrolment')`. CHECK: NOT NULL exactly for admin sessions (enforced in the service, because the role lives on `users`; asserted by a test) |
| created_at | timestamptz | NOT NULL: "signed in at" |
| last_active_at | timestamptz | NOT NULL: last sign-in or refresh |
| idle_expires_at | timestamptz | NOT NULL = last_active_at + idle(role) (client 30 d, admin 12 h) |
| absolute_expires_at | timestamptz | NOT NULL = created_at + absolute(role) (client 90 d, admin 7 d) |
| ended_at | timestamptz | NULL |
| end_reason | text | NULL CHECK `IN ('signed_out','signed_out_everywhere','revoked_by_user','revoked_by_admin','ended_by_admin','refresh_reuse','device_mismatch','password_changed','password_reset','mfa_replaced','disabled','replaced','ended_by_feature','expired')`. CHECK `(ended_at IS NULL) = (end_reason IS NULL)` |

Indexes:

- `device_sessions_live_device_key UNIQUE (user_id, device_id) WHERE ended_at IS NULL` (D-11)
- `device_sessions_user_live_idx (user_id) WHERE ended_at IS NULL` (lists, end-all)

**Expiry is computed, not stored.** A session is live iff `ended_at IS NULL AND @now < idle_expires_at AND @now < absolute_expires_at` (boundaries inclusive of expiry, spec Edge Cases). Expired sessions are not ended by a write. That would need a job and an audit entry for every expiry. `'expired'` is reserved in the CHECK list; the 003 housekeeping job (P-20) does not end sessions.

The per-request principal query (P-02):

```sql
-- name: GetSessionPrincipal :one
SELECT s.id, s.user_id, s.org_id, s.ended_at, s.idle_expires_at, s.absolute_expires_at,
       u.role, u.status
FROM device_sessions s JOIN users u ON u.id = s.user_id
WHERE s.id = @session_id;
```

## 3. `refresh_tokens` (spec: Refresh credential; FR-040, FR-041, FR-092)

| Column | Type | Constraints / notes |
|---|---|---|
| id | uuid | PK |
| org_id | uuid | NOT NULL FK orgs |
| session_id | uuid | NOT NULL FK device_sessions: the **family id** (plan P-03) |
| token_hash | bytea | NOT NULL CHECK `octet_length(token_hash) = 32` (SHA-256 of the raw `drt_…` string) |
| issued_at | timestamptz | NOT NULL |
| used_at | timestamptz | NULL |
| replaced_by | uuid | NULL FK refresh_tokens(id). CHECK `replaced_by IS NULL OR used_at IS NOT NULL` |

Indexes:

- `refresh_tokens_hash_key UNIQUE (token_hash)`
- `refresh_tokens_one_live_key UNIQUE (session_id) WHERE used_at IS NULL`: at most one unused credential per family.
- `refresh_tokens_session_idx (session_id)`: ending a family and the housekeeping purge.

A refresh credential has no expiry of its own: it lives exactly as long as its session.

## 4. `admin_mfa` (spec: Authenticator enrolment; FR-060…064, D-14)

| Column | Type | Constraints / notes |
|---|---|---|
| user_id | uuid | PK, FK users |
| org_id | uuid | NOT NULL FK orgs |
| secret_enc | bytea | NULL: confirmed secret; AES-GCM envelope with AAD `admin_mfa.secret:<user_id>` |
| pending_secret_enc | bytea | NULL: secret under enrolment or replacement; AAD `admin_mfa.pending_secret:<user_id>` |
| pending_created_at | timestamptz | NULL. CHECK `(pending_secret_enc IS NULL) = (pending_created_at IS NULL)` |
| last_used_step | bigint | NOT NULL default 0: the highest accepted TOTP step (replay guard) |
| enrolled_at | timestamptz | NULL. CHECK `(secret_enc IS NULL) = (enrolled_at IS NULL)` |
| updated_at | timestamptz | NOT NULL |

A row exists only for admins (enforced in the service and tested). "Enrolled" means `secret_enc IS NOT NULL`.

## 5. `mfa_recovery_codes` (spec: Recovery code set; FR-062, US-5 s6, s10)

| created_at | timestamptz | NOT NULL |

Indexes:

- `mfa_recovery_codes_usable_idx (user_id) WHERE used_at IS NULL AND revoked_at IS NULL`

## 6. `mfa_challenges` (spec: Interim second-factor proof; FR-023, D-14)

| Column | Type | Constraints / notes |
|---|---|---|
| id | uuid | PK |
| org_id | uuid | NOT NULL FK orgs |
| user_id | uuid | NOT NULL FK users |
| token_hash | bytea | NOT NULL UNIQUE CHECK `octet_length = 32` (SHA-256 of `dmc_…`) |
| purpose | text | NOT NULL CHECK `IN ('verify','enrol')` |
| device_id | uuid | NOT NULL |
| device_name | text | NOT NULL CHECK length 1–100 |
| platform | text | NOT NULL CHECK as in device_sessions |
| client_type | text | NOT NULL CHECK as in device_sessions |
| created_at | timestamptz | NOT NULL |
| expires_at | timestamptz | NOT NULL = created_at + 5 min. Valid iff `@now < expires_at` |
| consumed_at | timestamptz | NULL: set when the session is created (single use) |

## 7. `auth_throttles` (spec: Failed-attempt record; FR-045, FR-046, D-08)

| Column | Type | Constraints / notes |
|---|---|---|
| org_id | uuid | NOT NULL FK orgs |
| scope | text | NOT NULL CHECK `scope IN ('signin')`. 004 extends the list in its own migration (for example `'otp_send'`, `'otp_verify'`). |
| subject | bytea | NOT NULL CHECK `octet_length = 32`: `BlindIndex("throttle", scope\|kind\|value)` with kind `user`, `email` or `mobile`. The identifier is **never** stored as typed. |
| failures | timestamptz[] | NOT NULL default `'{}'` CHECK `cardinality(failures) <= 5` |
| locked_until | timestamptz | NULL |
| updated_at | timestamptz | NOT NULL |

- The primary key is `(org_id, scope, subject)`.
- There is no FK to users, on purpose: unknown identifiers need rows too.
- Rows are deleted on successful sign-in, on password reset (user subject), and by the `auth.housekeeping` job once stale: `updated_at <= @now - 15m AND (locked_until IS NULL OR locked_until <= @now)` (plan P-20). Lockout correctness never depends on the purge. The table stays tiny, so no extra index.

## 8. `audit_log` (001, unchanged columns)

Written only through 002's `internal/platform/audit` (`audit.Write`, which requires a transaction in the context and uses 002's `InsertAuditLog` in `queries/platform.sql`). 003 makes one additive change (plan C-4): `audit.Entry.At` is passed as `created_at` (`COALESCE(sqlc.narg('created_at'), now())`, so 002's calls without `At` keep the column default), and `uuid.Nil` for `EntityID` or `Actor.ID` is stored as NULL. Existing guarantees stay: append-only (`forbid_mutation` trigger) and `actor_kind IN ('admin','client','system')`.

### Audit action catalogue (US-11; one entry per event; `entity='user'` unless stated)

One operation can record more than one event, and each event gets exactly one entry in the same transaction: enrolment confirm writes `auth.mfa.enrolled` and `auth.sign_in.succeeded` (`mfa_method=enrolment`); sign-in with a recovery code writes `auth.mfa.recovery_code_used` and `auth.sign_in.succeeded` (`mfa_method=recovery_code`); the 5th failure writes `auth.sign_in.failed` and `auth.lockout.started`; disabling writes `auth.user.status_changed` (its `after` lists the ended session ids).

| action | actor_kind | entity_id | `before` | `after` (typed struct; never secrets) |
|---|---|---|---|---|
| auth.sign_in.succeeded | client / admin | user | – | session_id, platform, client_type, ip, mfa_method?, replaced_session_id? |
| auth.sign_in.failed | system | user or NULL | – | reason (`wrong_password`, `unknown_identifier`, `locked`, `not_active`, `wrong_totp`, `wrong_recovery_code`), identifier_kind, subject_ref (8-byte hex, only when entity_id is NULL), ip |
| auth.lockout.started | system | user or NULL | – | locked_until, subject_ref?, ip |
| auth.mfa.challenge_issued | system | user | – | purpose, platform, ip (extra event; records the challenge row mutation) |
| auth.session.refreshed | client / admin | user | – | session_id, ip |
| auth.session.refresh_reuse_detected | system | user | – | session_id, ip |
| auth.session.device_mismatch | system | user | – | session_id, ip |
| auth.session.signed_out | client / admin | user | – | session_id |
| auth.session.signed_out_everywhere | client / admin | user | – | session_ids[] |
| auth.session.revoked | client / admin | user (owner) | – | session_id, by (`user` or `admin`) |
| auth.session.ended_all_by_admin | admin | user | – | session_ids[] |
| auth.session.ended_by_feature | system / admin (caller decides) | user | – | session_ids[], feature (FR-054) |
| auth.password.changed | client / admin | user | – | ended_session_ids[] |
| auth.password.reset | system | user | – | ended_session_ids[], lock_cleared |
| auth.mfa.enrolled | admin | user | – | session_id |
| auth.mfa.replaced | admin | user | – | ended_session_ids[] |
| auth.mfa.recovery_codes_regenerated | admin | user | – | batch_id, count=10 |
| auth.mfa.recovery_code_used | admin | user | – | remaining, context (`sign_in` or `replace`) |
| auth.user.created | system / admin (caller) | user | – | role, status, email, mobile (the user's own contact data, ADR 0007; never for unknown identifiers) |
| auth.user.email_verified / auth.user.mobile_verified | system / admin (caller) | user | status | status |

| auth.admin.bootstrapped | system | user | – | email, org_id |
| auth.housekeeping.purged | system | NULL (`entity='auth'`) | – | throttles, challenges, refresh_tokens (counts); written only when a count is non-zero (plan P-20) |

## Lock order (deadlock avoidance)

Every transaction that takes several locks takes them in this order:

1. `users`: all admins ordered by id when guarding the last admin, otherwise the single user
2. `device_sessions`
3. `refresh_tokens`
4. `admin_mfa`
5. `mfa_recovery_codes`
6. `mfa_challenges`
7. `auth_throttles`

The bootstrap advisory lock comes before everything. Failure paths lock only `auth_throttles`. The housekeeping job runs one single-table `DELETE` at a time (throttles, then challenges, then refresh tokens of long-dead families) and never waits on `users` or `device_sessions`, so it cannot form a lock cycle with a refresh.

## sqlc

All 003 statements live in `apps/api/queries/auth.sql` (plus the `created_at` parameter added to 002's `InsertAuditLog` in `queries/platform.sql`) and are generated into `internal/platform/db/dbgen` with 002's uuid override. There is no string-built SQL. Every time comparison takes `@now`, and no behavioural query uses `now()`. After each edit, run `sqlc generate && sqlc vet`.

## Housekeeping queries (`auth.housekeeping`, plan P-20)

Each takes `@org_id`, `@now` and a row cap (1,000):

- `PurgeStaleThrottles`: rule in section 7.
- `PurgeExpiredChallenges`: `expires_at <= @now`.
- `PurgeDeadFamilyTokens`: `refresh_tokens` whose session has `ended_at <= @now - 30 days` or `absolute_expires_at <= @now - 30 days`. `device_sessions` rows themselves are kept (device history for the admin, small).

## Down migration

Drop the seven tables in reverse dependency order. `audit_log` and `orgs` are untouched.
